## Rule of direction

```
external source / runtime observation
        ↓
departments/minecraft research + evidence
        ↓
explicit adoption decision
        ↓
deliverables/minecraft/<product>
        ↓
build / GameTest / Tank evidence
        ↓
own failure-repair history + reusable lessons
        ↓
back to research/knowledge only through normal review
```

A product may generate new reusable knowledge, but product code is never itself treated as canonical technical truth without the normal evidence/review path.
