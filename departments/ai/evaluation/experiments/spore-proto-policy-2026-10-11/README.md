# Proto Hivemind — 再現可能な軽量学習の合成比較実験

**2026-10-11 / AI部門の独立実験・実行済み / Minecraft実機未起動。**

Minecraft原作の証拠は [Spore 2.2.0jの実Bytecode調査](../../../../minecraft/mods/fungal-infection-spore/HIVEMIND-AI-BYTECODE-2026-10-11.md) に属する。このディレクトリは**自作の数学的マイクロモデル**であり、原作JAR・Forge・ゲーム世界を実行するものではない。

## 再現方法

~~~bash
python3 probe.py --seeds 256 --episodes 1200 > results.json
~~~

- 実験実行環境: Linux、Python 3.13.5、random.Randomで再現する0〜255の固定シード。実験スクリプト独自のSHA-256: a2fed3b6286748b07f22c46e238a7ff22d011d5bf81abbfbdcbff5263b8485d2。
- 実際に実行した出力: [results.json](results.json)、SHA-256: fa085b88ad9c375a470bd873ea74a8e10f5124c2792defc974ca87c9c34493f7。2回連続実行の出力が一致した。スクリプト自身に基本契約のassertがある。
- 合成入力: 4種のone-hot特徴を均等に選び、各学習器は同じseed・初期重み16個・同じ入力列を受け取る。毎回正誤に応じて+0.05/-0.10を加える。
- **課題A（conditional）**: 入力特徴iと同じ番号の部隊iが最適。
- **課題B（global_best）**: 入力に無関係に部隊2が最適。
- 指標: 1,200試行後に4入力すべてを評価した正解率を、256 seedで平均。last300は最後の300判断の正解率。負数の重み数も記録する。

## 結果：最終状態の正解率

| モード | 課題A：入力ごとに部隊を変える | 課題B：常に部隊2が最適 |
| --- | ---: | ---: |
| frozen: 学習なし | 21.68% | 26.46% |
| proto_row: 原作から抽出した行全体の重み更新 | **25.59%** | **100%** |
| feature_gated: 当部門の入力特徴ごと更新する改良案 | **100%** | **100%** |
| proto_row_plus_morale: 士気補正の条件を合成周期で再現 | **34.77%** | **100%** |

**解析:** 原作の重み更新は、選ばれた部隊の4つの重みを同一値だけ動かすので、区別すべき入力特徴に対する独立した重みの変更がない。合成課題Aでは行動間の干渉が生じ、最終平均はおおむね25%に留まった。一方、合成課題Bでは部隊2を優遇する全体的な選好を学習できた。

**重要な留保:** この正解率は、ユーザーとの対戦・実際のMinecraft内の敵の強さ・勝率・TPSではない。入力分布と正解部隊は独自に設計した。feature_gatedは**原作に存在しない独立の比較案**。moraleは原作では1200エンティティtick条件だが、この小実験では**1試行=仮に200tick**として6試行ごとに判定している。実ゲームのタイミングや部隊の変換・ランダム選択は再現していない。原作RandomSourceの乱数bitとの同一性もない。

## 独立して検査した原作契約

- 4×4線形スコア、同点で最初の決定を選ぶ。
- 部隊行の4重みを成功時+0.05/失敗時-0.1、通常は[-1,1]clamp。
- 特別なmoraleBoostは重みの半数超が負ならランダム加算し、clampしない。
- all-zero入力時は部隊0へ固定。
- 元JARの初期部隊リストはfillDefaultTeamsで各4件になる。部隊番号jをmember番号へ誤記録する経路があるため、4件の一様抽選の場合に実候補kと違う確率は75%（静的計算）。ゲーム中の候補変換成功は未測定。
- 3 Biomassで5体×2をすべて消費した場合の負数到達は算術上可能（召喚成功条件は未シミュレーション）。
