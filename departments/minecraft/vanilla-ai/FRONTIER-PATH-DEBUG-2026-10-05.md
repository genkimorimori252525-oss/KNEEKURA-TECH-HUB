## Navigation and search

| Inspected component | Shared mechanism and exact difference or limit |
|---|---|
| PathNavigation constructor /createPath | Finder's constructor budget remains floor(FOLLOW_RANGE×16), while searches pass the current follow range and visited multiplier. Modern attributes use Holder descriptors. The cached-path shortcut may return a retained unfinished route when its target is in the requested set. A newly returned Path is not adopted by createPath itself. |
| recomputePath | The time test remains strictly greater than20 ticks, with delayed recomputation otherwise. A valid target causes a new search and updates the recompute timestamp/flag. This is a gameplay operation; a viewer must not invoke it to obtain evidence. |
| moveTo(Path,double) /Path.sameAs | Null clears the route. Otherwise replacement depends on coordinate-only sameAs: equal node counts and XYZ can retain the old Path despite different costs, target, reach status or cursor. Completion is a virtual PathNavigation.isDone call; its inspected base checks the retained Path. Subclass overrides remain authoritative. Trimming, nonempty-node and completion gates precede successful movement setup. |
| followThePath | Waypoint tolerance still depends on width: width/2 above0.75, otherwise0.75−width/2. XZ proximity with Y difference below1, or the corner/direction predicate, can advance the cursor before stuck detection. This does not prove arrival or collision freedom. |
| PathFinder | The prior exact search comparison retains prepare/start/inner/done, visited budget before heap pop, Manhattan target accuracy, walked-distance and effective-node-cost checks,1.5-weighted heuristic and distinct reached/partial selection. Modern DEBUG has actual ConstantValue false. Similar search structure is not proof of equal terrain classification, tie outcome, loader behavior or every subclass distance implementation. |

The original Warden/XZ-distance and anonymous Navigation explanations remain ANCHOR facts. Modern inheritance membership and exported subclass bodies provide lookup provenance, not a new modern-runtime or exhaustive branch acceptance claim.

## Terrain, effective malus and lifecycle

| Inspected component | Actual modern source compared with ANCHOR |
|---|---|
| NodeEvaluator.prepare /done | prepare creates PathfindingContext, retains Mob, clears the node map and computes dimensions. done clears context/Mob references without clearing that map. The prior exact cache study explains ServerLevel's shared raw-type cache and one invalidation site. An additional classification query can mutate that cache. |
| PathType defaults | All25 ANCHOR names retain their declared numeric defaults. Modern adds DANGER_TRAPDOOR with default0, making26. These are enum defaults, not per-Mob effective getter values, accepted-node costs or rejection reasons. The compiler support-switch owner was not inspected here; no specific support-enum mapping is inferred from its numeric case labels. |
| Mob.getPathfindingMalus | Controlled-vehicle inheritance still requires a Mob vehicle whose shouldPassengersInheritMalus permits it; otherwise the Mob map or enum default supplies the value. Virtual getters and MOD transformations may differ. |
| Amphibious preparation /done | WATER is set to0; WALKABLE and WATER_BORDER are temporarily6 and4, then only those two saved costs are restored. done does not restore WATER. This is state mutation by the evaluator, not a passive observer operation. |
| Fly /Swim accepted nodes | Fly takes the maximum of retained node cost and effective type cost, then adds1 for WALKABLE. Swim accepts WATER or allowed BREACH with nonnegative effective cost, takes that maximum, then adds8 when the queried fluid is empty. Reusing the same cached Node can retain additive mutations; enum defaults alone cannot explain its final cost. |
| Walk acceptance and step | Modern retains the accepted-node concept but splits blocked/closed/jump/non-water/ground helpers and changes terrain API to PathfindingContext. Jump height uses max(1.125, maxUpStep), whereas the Forge ANCHOR caller uses getStepHeight. Descriptor/name replacement alone cannot backport the hook or equate the underlying step implementations. |
| Volume classification /doors /rails | Modern volume classification applies open/pass-door flags and rail-to-unpassable transformations inside the bounding-volume scan. Closed wooden doors become WALKABLE_DOOR only with both flags; open doors become blocked when passing is disabled. Ground and Flying canOpenDoors getters still actually read canPassDoors. Names are insufficient evidence of the flag being observed. |
| Raw block classification | The inspected official classifier handles trapdoor/lily-pad/dripleaf, powder snow, damaging blocks, fluids, doors, rails, leaves, fences and land pathfindability. Door hand-opening uses BlockSetType.canOpenByHand. It lacks the Forge block/fluid callback surfaces present in ANCHOR; this says nothing about transformed NeoForge/MOD bodies. |
| Neighbor hazards | The inspected24 surrounding cells exclude the central vertical column. Classification returns the first matching hazard, including damage/fire/lava/water/cautious mappings, rather than computing a global maximum over hazards. Modern queries context types; ANCHOR's adjacent Forge callbacks require separate version-specific handling. |

Keep raw type, enum default, effective Mob getter, accepted/rejected evaluator return and mutated Node.costMalus distinct in a numeric view. No modern classifier/cache call becomes a passive ANCHOR observation, and no additional modern member enters ANCHOR readiness.

## Typed transport does not activate capture or drawing

| Layer | Confirmed difference or retained boundary |
|---|---|
| Producers | Modern sendPathFindingPacket, sendGoalSelector and sendEntityBrain each immediately return. Typed payload classes and registered codecs establish a protocol surface, not an active server producer. Neither generation's inspected sender establishes complete original frontier capture. |
| Path payload | ANCHOR channel order is entity ID, maximum waypoint distance, then Path. Modern encoder/decoder order is entity ID, Path, then maximum distance. These wire layouts are incompatible. |
| Goal payload | ANCHOR puts BlockPos before entity ID and a fixed int list count. Modern puts entity ID before packed BlockPos and collection coding. DebugGoal still carries priority, running and name; the decoder explicitly bounds UTF at255, while the writer uses its default UTF overload. No new unbounded-name compatibility is claimed. |
| Brain payload | Modern BrainDump is a payload record with UUID/id and other header fields before Vec3 position; ANCHOR receives position before UUID. Activities, behaviors, memories, gossips and POI sets remain categories rather than full decision causes. The old renderer-inner BrainDump/DebugGoal owners are replaced by payload owners; accessors and descriptors change. |
| Path /debug data | Both writeToStream bodies can return without writing a body when debug targets are unavailable. Modern stores Path.DebugData separately: reached/index, packed target, node collection, then debug target collection/open array/closed array. ANCHOR uses the older order and fixed int counts. Modern node arrays use VarInt length. Copying one serializer into the other version is unsafe. |
| Node packet | XYZ, walkedDistance, costMalus, closed, type and f remain serialized concepts. g, h and cameFrom are absent. A packet cannot reconstruct missing predecessor/frontier truth merely from these values. |
| Decode /fallback | CustomPacketPayload's codec reads an identifier and selects a registered StreamCodec or fallback. The gameplay codec registers Path/Goal/Brain. Unknown DiscardedPayload uses a1MiB bound and skips its bytes. That fallback cap is not proof of an equal global cap for every known typed payload, unlike the older packet constructor constraint. |
| Client dispatch | The common listener discards unknown discarded payloads before thread handling; other payloads go through the same-thread gate and typed dispatch. ClientPacketListener branches call addPath, addGoalSelector and addOrUpdateBrainDump. ANCHOR's inspected channel decoding, Forge NetworkHooks and copied-buffer release are version-specific; no transport interoperability is established. |
| Root rendering | DebugRenderer.render still dispatches only its chunk-border interface and GameTest renderer. Path/Goal/Brain receipt is not proof of on-screen draw. Capture flags, received data and renderer dispatch require separate activation/measurement. |
| Path renderer | If invoked, it draws before removing entries older than5s from pathMap/creationMap; pathMaxDist is not removed there. It declares no clear override, and the interface default clear is a no-op. Modern renderPath guards debugData and can display debug nodes/type/cost labels; its render caller passes both options true, unlike ANCHOR's disabled label options. This is static presentation behavior, not verified pixels or GPU cost. |
| Goal /Brain renderer | Goal range remains160 from a camera block position with Y forced to0, with name/running presentation rather than control-lock/reason analysis. Brain draws before updating its last looked-at UUID; an eight-block optional target updates that retained field, and a missing target does not clear it there. Client selection is not server decision authority. |

The separately pinned [Moonlight precedent](DEBUG-INFRASTRUCTURE-RESEARCH-2026-10-05.md) demonstrates modern loader-specific activation, including reconstructed returned-node arrays. It is not an original search frontier and was not installed or copied into ANCHOR.

## Backport design and remaining work

Reuse the common observation contracts: optional stages, exact UUID/context/source identity, original invocation returns, retained samples and explicit unknowns. Keep ANCHOR BlockPathTypes/PathNavigationRegion, descriptors and original bounded producers. Modern PathType/context/DebugData/typed payload owners require independently versioned adapters. Validate serialization pairs explicitly; neither shared field names nor matching instruction shape makes them interoperable.

The exact-source portion of original B10 now has scheduler/search, controls/cache and this Path/terrain/debug comparison. Modern runtime hooks, every subclass branch, arbitrary future versions/loaders, complete cache invalidation and semantic equivalence remain unverified. No native acceptance or performance measurement was added. Original true Boss fields, same-case integrated scenarios, nine distinct cost measurements and the final whole-diff review remain active in [the reconciliation](ORIGINAL-REQUIREMENT-RECONCILIATION-2026-10-05.md).
