# ゲームの3Dモデル → マイクラ（Blockbench / ブロック）変換プレイブック

PSP の GMO モデル（ワルプルギスの夜）で確立した手順。次のモデルも、同じ順で・同じ検証で進める。
各ツールの詳細は [README.md](README.md)、形式の事実は [FORMATS.md](FORMATS.md)。

## 0. 成果物（作れる形）

| 形 | ツール | 用途 |
| --- | --- | --- |
| OBJ + PNG | `gmo2obj.py` | 形と色の確認、他ツールへの入力 |
| GLB（骨・ウェイト・アニメ） | `gmo2gltf.py` | Blender / Unity / MOD の自前描画 |
| `.bbmodel`（メッシュ・骨格・アニメ） | `gmo2bbmodel.py` | Blockbench で見る・編集する（マイクラ本体には載らない） |
| `.schem`（1.20.1 のブロック構成） | `obj2schem.py` | WorldEdit で建てる |
| **`.bbmodel` + `.geo.json`（立方体だけ）** | `hybrid2bbmodel.py`（推奨）/ `voxel2bbmodel.py` | **マイクラ・GeckoLib に載る立方体モデル** |

立方体モデルは `hybrid2bbmodel.py`（**斜めの板 + ブロック**）が最終形。`voxel2bbmodel.py`（全部ブロック）は比較用。

## 1. 手順（ワルプルギスで実際に使った値）

```bash
# 取り出し
python tools/isols.py <iso>                                             # 位置を見て CPK を切り出す
python tools/cpk_extract.py install.cpk out/ 'Scene_Dungeon/unit/<name>\.pac'
python tools/pac_extract.py out/Scene_Dungeon/unit/<name>.pac out/pac/
# 中間形
python tools/gmo2obj.py out/pac/<NAME>.GMO out/obj/
python tools/gmo2gltf.py out/pac/<NAME>.GMO out/<name>.glb --motion out/pac/<NAME>_*_*.GMO
# ブロック構成（建てる用）
python tools/obj2schem.py out/obj/<NAME>.obj out/<name>_128.schem --size 128 --exclude 'TR_pattern' --gain 1.3 --sat 1.3 --preview out/preview
# 立方体モデル（マイクラ・GeckoLib 用。最終形）
python tools/hybrid2bbmodel.py out/pac/<NAME>.GMO out/slanted --name <name>_slanted \
  --size 128 --unit 16 --texel 1.0 --thickness 0 --coverage 0.12 \
  --plates '^(AL_body|AL_head)' --plate-tex 'walpurgis_01' --fine-parts '^AL_head' --fine-texel 0.25
# 同じ立方体モデルに骨とアニメを付ける（GeckoLib / Bedrock のアニメとして書き出せる）
python tools/hybrid2bbmodel.py out/pac/<NAME>.GMO out/slanted_anim --name <name>_slanted_anim \
  （上と同じオプション） --rig --blend-step 0.1 --blend-budget 2.0 --blend-min-piece 4 --blend-margin 0.5 --join 0.02 \
  --blend-tol 0.25 --seam-report --dump-expected out/expected_rig.json --motion out/pac/<NAME>_*_*.GMO
# 変えるたびのチェックポイント（Blockbench を起動しておく）: 4 方向で撮り、前回と画素差で比べる
python tools/bb_checkpoint.py out/slanted/<name>_slanted.bbmodel out/cp_base                      # 基準（直す前／静止モデル）
python tools/bb_checkpoint.py out/slanted_anim/<name>_slanted_anim.bbmodel out/cp_new --baseline out/cp_base
# アニメで浮いて残るブロックの検査（Blockbench の実再生）
python tools/bb_float_check.py out/slanted_anim/<name>_slanted_anim.bbmodel out/float.json
```

## 2. 決めること（にーくらと決めた方針と理由）

1. **姿勢は元のまま**。ワルプルギスの逆さ吊りは特徴なので直さない。
2. **背景の板は除外**（結界の紋様 `TR_pattern`。平らで巨大、本体ではない）。パーツ名とバウンディングボックスを見て決める。
3. **中は空**（表面だけの殻）。スカートの内側は見える面なので埋めない。外から見えない閉じた空洞だけは埋めてよい（見た目は変わらず、軽くなる）。
4. **前は -Z**（マイクラのエンティティの北向き）。元データの前（顔の向き）を確認してから回す。
5. **色**: ゲームのテクスチャは暗めなので、明るさ・彩度 ×1.3 でブロック色（1.20.1 の標準 61 種）に寄せる。4 通りを並べて目で選んだ値。
6. **細かさ**: 最長辺 128 ブロック、1 ブロック = 1 ピクセル。にーくらは「細かさはこのままでいい」。
7. **なめらかな面は斜めの板にする**（「完全な立方体で構成しなくていい」）。
   - 板は**厚み 0**（元のメッシュの面そのもの）。厚みがあると、側面が継ぎ目で「浮き出した斜めの線」になる。
   - 板は**1 面だけ + テクスチャ両面表示**。表裏 2 面を同じ位置に置くと縞模様のチラつきになる。
   - ピクセルを塗る判定は **coverage 0.12**。0.5 だと継ぎ目に点線の隙間、低すぎると隣の板からはみ出す。
   - **抜き絵（レースの縁取りなど）は板にしない**。1 ブロック = 1 ピクセルに粗くすると枠だけの板になり、宙に浮いた線に見える → `--plate-tex` で本体テクスチャの面だけ板にし、飾りはブロックに残す。
8. **顔は細かく**（`--fine-parts '^AL_head' --fine-texel 0.25` = 1 ブロックに 4×4 ピクセル）。顔だけで十分に精密に見える。
9. **重さ**: 立方体は「色ごと」ではなく「形だけ」でまとめる（色はテクスチャが持つ）。見えない箱・面は出さない。geo.json は圧縮。
10. **アニメ**（`--rig`）: 元の骨をそのままグループにし、モーションをグループのキーにする。立方体は伸び縮みできない（1 つの骨に乗ると硬い）ので、
    元のスキニング（頂点ごとに複数の骨を混ぜる）とは次の 3 段で近づける。
    - **補助の骨**: 重みが 2 本以上に混ざる面は、重みを 0.1 刻みに丸めた「混ぜ方」ごとの親なしグループ（`blend_N`）に乗せる。
      その動きは毎フレーム、骨の変形を重みで混ぜた行列 M から作る（回転 = クォータニオンの重み付き平均、移動 = ピボット c の M·c - c）。
      行列のまま混ぜると、回り続ける部品で潰れる（特異行列）。
    - **伸び縮みする面は切る**（`--blend-budget 2`）: 1 つの面の中で重みが大きく変わる所（スカートの骨の境目）は、面を 1 つの動きにすると
      継ぎ目が割れる。元の変形からのずれの見積もりが 2 ブロック以下になるまで面を 4 分割する（UV と頂点の重みは補間）。
      伸びない所は切らないので、板が増えるのは必要な所だけ。
      **小片は 4 ブロック未満にしない**（`--blend-min-piece 4`）。小さい面（胸・袖）まで切ると、絵が 1〜2 ピクセルの板になりモザイク状に壊れる。
    - **結合処理**（`--join 0.02`、にーくらの案）: スカートは部分ごとのバラバラな動き（はためき）を残したまま、各時刻で補助の骨（剛体）の
      位置と向きを少しずつ寄せ、継ぎ目の頂点（元のメッシュでは同じ頂点）を一致させる。元の動きから離れすぎないよう補正に罰 λ を付けて
      釣り合わせる（Jacobi 反復、3 フレームごとに解いて間は補正を線形補間、前の時刻の解から始める）。伸びの隙間が 1 か所に集まらず
      周りの継ぎ目に散るので、下の「重ね」で隠れる大きさになる。
    - **切った小片は少し重ねる**（`--blend-margin 0.5`）: 隣と共有する辺だけを 0.5 ブロック外へ出す（服の縁などの外周は出さない）。
      角の移動は 1 ブロックまで（細長い三角形で角がトゲのように飛び出したため）。新しい角は元の平面上、UV も同じ重心座標で延ばす。
    - **ブロックは骨に関係なく一度にボクセル化**してから、各セルを一番近い元の三角形の骨に割り当てる（静止姿勢の形と色が骨なしの版と同じになる）。
    - **キーは許容誤差で間引く**（`--blend-tol 0.25` ブロック・回転 1°）。継ぎ目の開き（1〜2 ブロック）より細かくしても見た目は変わらず、重くなるだけ。
    - Euler は 2 通りの表し方から直前に近い方を選び、±360° も外す（回り続ける歯車が 1 コマで逆回りに飛ぶのを防ぐ）。回転は毎フレーム標本化してから間引く。

## 3. 検証ゲート（毎回。数字で合否を出す）

| 対象 | 確かめること | 合格 |
| --- | --- | --- |
| GMO 読み取り | 四角形の頂点順・面の向き（法線との一致） | 片方が 0 件（例: 634 / 0、2111 / 0） |
| 骨 | 逆バインド行列 = 骨ワールドの逆行列 | 誤差 < 0.01 |
| GLB | Khronos 公式バリデータ（npm `gltf-validator`） | エラー 0・警告 0 |
| `.schem` | `schem_check.py` と `nbtlib` の両方で読み直す。ブロック ID を minecraft-data の一覧と照合 | 寸法・パレット・セル数・材料表が一致、未知 ID 0 |
| 立方体モデル | `bb_verify_hybrid.py`（Blockbench 実機）: 板の 4 隅の位置、板の全画素、ブロックの全露出面の色、自作 geo.json と Blockbench 書き出しの一致 | 4 隅誤差 < 0.01、色の不一致 0、geo の差 0 |
| アニメ（骨） | `bb_verify_rig.py`（Blockbench 実機）: 全キューブが正しいグループにあるか、各アニメ・時刻で全頂点が骨の変形どおりか、geo.json の骨が Blockbench 書き出しと一致するか | 所属違い 0・geo の差 0・通常の骨の誤差 < 1 単位、補助の骨は間引きの許容誤差程度 |
| アニメ（継ぎ目） | `--seam-report`: 元のスキニングではつながる共有頂点の開き（結合前）と、結合処理の前後（解いた時刻） | 前の版より悪化しない（ワルプルギス: 結合後 最大 2.7・p99 1.0・中央値 0.1 ブロック） |
| **チェックポイント（変えるたび）** | `bb_checkpoint.py`: 前・右・後・左を小さく撮り、前回（基準）と同じカメラで画素差。差の数値だけ見て、印の付いた向きだけ画像を見る | 変えていない版どうしは 0.01% 以下。直した所以外に赤が出ていない |
| **浮いて残るブロック** | `bb_float_check.py`（Blockbench の実再生）: 静止時に触れ合うキューブのつながりが、再生中に切れて本体から離れる小さいまとまり（20 個以下）で、自分のグループの大半は本体に残っているもの | 0（部品ごと離れる歯車などは数えない。ワルプルギスは歯車の小片 7 個だけで、それも骨ごとの正しい動き） |
| 見た目 | Blockbench で全体・気になる所（スカート・顔）を近くから撮って並べる。アニメは割れが最大の時刻を下からも撮る | にーくらが目で判断 |

Blockbench の起動: `Blockbench.exe --remote-debugging-port=9333 --user-data-dir=<使い捨てフォルダ>`（本人の設定に触れない）。
検証が終わったら、自分で起動した Blockbench だけを終了する。

## 4. 落とし穴（実際に踏んだもの）

- API 経由で `.bbmodel` を読むとプロジェクト設定ダイアログが開く → `Dialog.open.cancel()`。
- 同じページで検証 JS を何度も評価すると `const` が再宣言エラー → 変数名を実行ごとに変える。
- タブを積むと Blockbench が肥大（約 20 個で 1.7GB）してタイムアウト → 定期的に再起動。重い検証は `BB_TIMEOUT_MS` を延ばす。
- Blockbench の編集モードで骨を動かすと**束縛姿勢が更新される**（変形しない）→ 変形の確認はアニメ再生で。
- 自作 NBT 読み手で「代入は右辺が先に評価される」バグ → 名前を先に読んでから値を読む。
- テストの前提ミス: 閉じた殻は空洞を埋めると箱 1 個になる → 穴のある殻で試す。
- PowerShell 5.1 の `Set-Content -Encoding utf8` は BOM を付ける → コミットメッセージ等は BOM なしで書く。
- 出力フォルダの `Remove-Item *` は保護で止まることがある → 上書きか、パスを明示して消す。
- **継ぎ目の物差しを甘くしない**: 板ごとの平均の重みと比べると「最大 0.7 ブロック」に見えたが、頂点ごとの重み（本当のスキニング）で
  継ぎ目の開きを測ると 17 ブロック割れていた。物差しは必ず元データの頂点ごとの重みで作る（`--seam-report`）。
- 割れの原因は「面が大きい」こと（スカートの面は中央値 16・最大 53 ブロック）。補助の骨だけでは直らず、面を切って初めて縮む。
  重みの刻みを細かく（0.05）しても、補助の骨が 1.6 倍・ファイル +40% のわりに最大の割れは 4.5→4.1 ブロックしか縮まない。
- 正面からの比較画像では割れが見えないことがある。割れが最大の時刻・場所を計算で探し、その場所を下からも撮る。
- **撮影した姿勢が本当にその時刻か確かめる**: Blockbench の窓が裏にあると描画（requestAnimationFrame）が止まり、骨は動いていても
  画面は古い姿勢のまま撮れる（違うアニメ・時刻の画像が 1 画素も違わなかった）。`bb_load_pose.py` は `Preview.render()` を明示的に呼ぶ。
  比較の前に、違う時刻の 2 枚が実際に違うことを画素差で確かめる。
- **直した所しか見ないと、ほかを壊しても気づかない**: スカートの割れを直す変更が、胸・袖をモザイク状に、細長い三角形の角をトゲにしていた
  （にーくらが見つけた）。変えるたびに 4 方向のチェックポイントで前回と比べる。比べるときは前回と全く同じカメラ（`camera.json`）で撮る
  （外接箱から毎回カメラを決めると、構図がずれて 10〜17% の偽の差になった）。
- `build()` の中で `l` は寸法（`w, h, l = dims`）。ループ変数に `l` を使って上書きし、その後の座標変換が全部ずれた（結合処理が
  間違った点へ寄せて、板が破片のように飛び散った）。一部だけを関数で直接呼ぶ小さな再現（1 アニメ）で、build 経由と値を突き合わせて見つけた。
- JS のテンプレートの置き換え文字は他と重ならない名前にする（`THR` が `THREE` の中まで置き換わり構文エラー）→ `__THR__` のように。
- 浮きの検査は「頂点そのものの動き」と比べると、回る歯車の大きな箱で回転半径の違いを誤検出する。また元の LBS と比べると、
  大きく回る骨どうしの混ぜ（元のメッシュ自体がつぶれる所）で誤検出する。「静止時のつながりが再生中に切れて、小さく取り残されたか」で見る。

## 5. ワルプルギスでの実測（128 ブロック版）

| | 全部ブロック（旧） | 全部ブロック（軽量化） | **斜めの板 + ブロック（最終）** |
| --- | --- | --- | --- |
| キューブ | 8,259 | 5,851 | **2,890**（ブロック 2,255 + 板 635） |
| 描画する面 | 49,554 | 29,871 | **11,942** |
| `.geo.json` | 9.0MB | 1.5MB | **0.7MB** |
| Blockbench 読み込み | 5.6 秒 | 3.8 秒 | **0.4 秒** |

アニメ付き（9 モーション、`--rig`）:

| | 骨 1 本に固定 | 補助の骨だけ | 補助の骨 + 伸びる面を切る | **+ 結合処理 + 重ね（最終）** |
| --- | --- | --- | --- | --- |
| 継ぎ目の開き 最大 / p99 / 中央値（ブロック） | 23 / 11.6 / – | 17.5 / 6.4 / 0.13 | 4.5 / 2.5 / 0.50 | **2.7 / 1.0 / 0.10** |
| キューブ（うち板） | 3,979 | 4,037（635） | 5,260 | **5,649（1,398）** |
| グループ（骨 + 補助） | 37 | 119 | 258 | **258** |
| `.bbmodel` | 4.7MB | 7.7MB | 10.2MB | **10.5MB** |
| 静止姿勢の差（静止モデルと 4 方向） | – | 0.00% | 0.2〜0.4% | **0.2〜0.4%**（レースの縁の陰影のみ） |

結合処理で元の動きから離れる量は、試算で中央値 0.4・p95 1.5 ブロック（はためきは残る）。
立方体は伸び縮みできないので、完全に閉じるには面を 1 ブロック以下まで切る必要があり（試算: 板 1 万超・補助の骨 1 千本超）、重さに見合わない。
