# ANCHOR: transformation, Mixin adaptation and coremod pipeline

## Result and scope

Connector beta.50 implements a staged compatibility rewrite, not a universal Fabric-to-Forge equivalence proof. It admits Fabric artifacts through discovery/resolution, translates intermediary bytecode and metadata to the resolver's current namespace, then applies Forge-specific compatibility patches. It also modifies the host-side class view and ships coremods that recreate selected vanilla-facing shapes. Cache hits and Loom-generated library artifacts take materially different paths.

This report covers all **22 Java files** beneath `transformer/` and **five JavaScript files plus coremods.json**, with full-file static reading. Eight supporting files were read for call sites, metadata, cache identity and dependency declarations. Each file's SHA-256 and immutable source locator is in the companion coverage inventory. Revision: `7f68ac02291fde986119a3f5cab85436bed5c350`. No target code, build, test, Minecraft runtime or coremod script was executed. The acquired repository is complete for this finite path scope; the matching external dependency/data/binary closure is not. Capture-index namespace labels are metadata, not proof of runtime mapping direction.

Source-declared versions include Minecraft 1.20.1, Forge 47.4.6, Connector 1.0.0-beta.50, fork Fabric Loader 2.7.15+0.19.3+1.20.1, FART 1.0.14 and Adapter definition 1.11.67-1.20.1. These are declarations at the pinned source revision, not an attestation of the installed release artifact. ## Why this bridges two different modding environments

There are two different problems. First, Fabric bytecode names intermediary Minecraft classes and members; the renamer translates those symbols into the host resolver's namespace. Second, Forge has changed actual Minecraft code shapes and extension contracts, so a successfully renamed Mixin can still point at a removed instruction, a different method, a changed field type or an incompatible handler signature. Connector therefore combines name translation with targeted semantic adaptation. Neither layer substitutes for the other.

A precise example is the armor renderer. For the exact HumanoidArmorLayer ModifyArg selector with index 4, Connector requests that the injection move from a renderModel call using HumanoidModel and a String texture argument to Forge's overload using general Model and ResourceLocation. It changes the handler parameter/return contract to Model→Model, inserts casts where HumanoidModel-specific use remains, and adds an instanceof guard that returns an unrelated Model unchanged. Merely renaming methods could not supply those argument/return and control-flow changes. This is a deliberate compatibility policy for that matched shape, with the tradeoff that the original handler is bypassed for a non-HumanoidModel supplied by Forge-side code. [Exact armor adaptation](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/MixinPatches.java#L586-L615)

The declaration and inline ASM operations are directly visible here; whether a real mod's selector matches, its generated bytecode verifies, and its desired behavior survives is not established here. Adapter source tracing can reduce the dependency uncertainty; runtime acceptance is outside this task. This report does not reuse an unrelated fixture or another Connector version as beta.50 runtime evidence.

## 2. Normal jar pass order

Before constructing the renamer, refmaps are loaded/remapped and merged; the per-jar accessor redirector is created; Adapter serialized patches are concatenated with 15 accessor patches; a per-jar refmap holder and PatchEnvironment are built; Fabric LVT compatibility is inferred from loader dependency intervals. Impossible intervals throw, absent dependency constraints use compatibility 0.10.0, and lower versions/unbounded lower ranges can choose 0.9.2. [JarTransformInstance.java:122–133](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/jar/JarTransformInstance.java#L122-L133) [FabricMixinBootstrap.java:103–143](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/service/FabricMixinBootstrap.java#L103-L143)

At this call site, metadata has already passed `removeAliasedModDependencyConstraints`, which removes standard `fabricloader` edges unless an earlier configured alias match takes the wildcard/BREAKS branch. A mod whose only loader constraints use that ID, without such an alias match, therefore reaches the default 0.10.0 compatibility branch. Interval selection here requires a surviving recognized constraint such as `fabric-loader`, or an alias-produced constraint. This is a source-path deduction, not a runtime observation. [Metadata preprocessing](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/jar/JarTransformer.java#L177-L184), [ordered constraint policy](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/locator/DependencyResolver.java#L81-L100)

The explicit registration order is:

1. `JarSignatureStripper`
2. One `ClassNodeTransformer`, internally field-to-getter → accessor call renames → reflection triple-string analysis

## 3. Mapping directions and member lookup

`SOURCE_NAMESPACE` is intermediary; `OBF_NAMESPACE` is srg. The code primes both intermediary↔srg resolver maps, but its principal forward mapping comes from `getCurrentMap(intermediary)`. Therefore names such as `intermediaryToSrg` and `SrgRemappingReferenceMapper` do not establish an unconditional SRG output namespace. The actual current namespace and mapping payload come from the fork Fabric Loader resolver and launch environment. SRG→intermediary is specifically used to translate Forge-authored field/accessor targets back into the input vocabulary. ### Fast and fallback maps

- `IntermediateMapping` is cached by source namespace. Its supported prefix table has intermediary class/field/method/record-component prefixes only. It builds a name-only map; a conflicting mapped name is removed and both entries moved to descriptor-qualified keys. Fields use `name:descriptor`; methods use `name+descriptor`. Lookups try the simple map first, then the qualified map. Nullable lookups may return null; only `mapMethodOrDefault` explicitly returns the original name. This is a local flat-map implementation, not proof that every possible duplicate-name topology is resolved. ## 4. Refmaps: lookup, conversion, exposure and generated entries

Each collected refmap name is sought inside the input jar. On absence, library paths are scanned, resolving directories directly or opening jar filesystems. The first match wins; any exception opening a library logs and returns null immediately rather than continuing to later libraries. The exclusion compares Path object identity (`==`), not value equality. Library filesystems opened by the helper have no explicit close in that helper. Missing resources warn and the pipeline continues. Read/parse failures are not equivalent to the missing-file fallback. [RefmapRemapper.java:39–86](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/RefmapRemapper.java#L39-L86)

Conversion preserves each mixin key and each original reference key, remapping only its value. It processes default `mappings` and every environment under `data`; `named:intermediary` is renamed `searge`, while other labels survive. Methods are indexed globally by original name+descriptor, fields by original name, retaining the first collision; owner and descriptor strings remap independently. A missing member name mapping keeps the original name. A non-method/non-field reference is passed to class remapping. The owner is not used to disambiguate those member indexes. [SrgRemappingReferenceMapper.java:23–78](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/SrgRemappingReferenceMapper.java#L23-L78) [RefmapRemapper.java:151–156](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/RefmapRemapper.java#L151-L156)

## 5. Field getters, accessor redirects and access wideners

The shared replacement table contains 15 fields across 12 classes: Biome climate/effects; Structure settings; MobEffectInstance effect; LiquidBlock/BucketItem fluids; StairBlock model block/state; FlowerPotBlock content; ItemStack item; MobBucketItem fish type/sound; and Connector-provided particle/block-color/item-color views. Forge SRG field names become input intermediary names; getter names use ASMAPI mapping. The class mapper for every listed owner is required and a missing entry fails construction. [FieldToMethodTransformer.java:27–85](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/FieldToMethodTransformer.java#L27-L85)

The direct bytecode rewrite is name-based: matching GETFIELD **or GETSTATIC** instructions become INVOKEVIRTUAL getter calls on the original owner, with `()` plus the original field descriptor. It does not check owner/descriptor or preserve static opcode in the matching condition. No actual problematic input was executed; the intended table and this shape restriction must be considered together. The corresponding AW resource is rewritten through a filter that suppresses listed names for both field and method callbacks. [FieldToMethodTransformer.java:87–149](https://github.com/Sinytra/Connector/blob/7f68ac02291fde986119a3f5cab85436bed5c350/src/main/java/org/sinytra/connector/transformer/FieldToMethodTransformer.java#L87-L149)

Accessor handling has two coordinated halves. An original-jar package scan applies analysis-only interface patches to record `owner → method name+descriptor → connector$redirect$...`; call instructions are renamed before bytecode namespace conversion. Later target patches replace an accepted @Accessor with @Invoker for the replacement getter and prefix the declaration name.
