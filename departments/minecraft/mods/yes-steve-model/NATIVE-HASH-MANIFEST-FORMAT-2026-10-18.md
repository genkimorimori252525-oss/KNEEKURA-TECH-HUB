# Archive hash-manifest numeric formatting (static contract)

## Result
The retained tree traversal writes each name as its explicit byte range, then literal byte `0a`, then its full **unsigned 64-bit integer** through the stream's `num_put` facet, then literal byte `0a`. The newly constructed stream starts with **decimal | skipws (0x1002), width 0, precision 6, no tie, exception mask 0**. With the standard classic facets and successful output, integer text is unpadded unsigned decimal, including zero as one digit, without sign, base prefix, leading zeroes, or scientific notation. This last ASCII/no-grouping description is conditional: the stream inherits the then-current C++ global locale; this call site does not force the classic locale. Original-runtime locale, custom facets and actual output success remain unknown.

## Locale and failure bounds
`2e4f54` default-constructs locale via `2f7d50`, then assigns it at `2e4f63`. The constructor initializes locale infrastructure, reads global-implementation pointer through `d2d370`, and stores that implementation (`2f7d60..71`); it does not explicitly choose classic. `2e4d00` caches ctype/num_put/num_get facets from it. The checkpoint's global/classic pointers happen to agree, but this is not evidence for an actual Forge launch or later stream construction. Grouping, widened digit atoms, custom num_put behavior and a changed global locale must stay conditional. Locale names/environment variables are not inferred.

Sentry `2f8b50` permits output only in good state, otherwise may add failbit when badbit is already present. Numeric insertion tests the returned iterator failure byte (`2f96ae`) and sets badbit (`2f9730..40`); its exception handlers also set badbit, with a rethrow branch (`2f97ea..2f988e`). `2e4c60` throws on state intersecting exception mask; mask defaults to zero, so ordinary output failure need not immediately throw. String and byte output also mark badbit on short write/EOF. Ordinary errors can therefore leave partial buffer contents and suppress later insertions; allocation, construction, string retrieval and forced unwind can still escape. This is not a claim that all failures are swallowed or that every catch type was recovered from EH metadata.

After iteration the caller does **not** check rdstate: `3d8d09` retrieves buffer content with `31ee10`, then `3d8d13` uses its explicit length for hash at `3d8d25`. Retrieval copies the buffer extent and terminates the returned string separately (`31ee81..85`); the terminator is not included in the length hashed. A failure-state path that returns normally therefore hashes whatever buffer content retrieval returns, not a proved complete manifest. The unchanged comparison at `3d8de5` is still against `0x048417704ddff4de`; mismatch branches to `3daa88`. No actual data or aggregate was computed and no success outcome is inferred.
