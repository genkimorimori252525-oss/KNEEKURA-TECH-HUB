# Final implementation proposal: YSM isolated server smoke

Authoritative design, 2026-10-18. This replaces earlier demands for an independently audited full dependency closure, duplicate JVM tarball hashes, an advance exact JVM build label, or cross-run deterministic installer outputs. Status is IMPLEMENTATION_READY_DESIGN / NOT_EXECUTABLE, authored harness review now completed; explicit bounded approval remains absent. Nothing has been installed, executed, published or dispatched.

## 1. One bounded experiment

Use one ephemeral standard GitHub-hosted ubuntu-24.04 VM. Inside it, use the pinned Microsoft OpenJDK17 Ubuntu22.04 Linux/amd64 container for (a) isolated official Forge installer staging, (b) clean production Forge server control and (c) identical production server plus original YSM. No clients/players, renderer, GPU, paid coding agent or self-hosted/user-PC runner. Control and YSM get separate new writable game/home/temp directories; both consume the same frozen installed runtime snapshot.

The official installer is the trusted bootstrap component. This is **trusted bootstrap plus one-cohort snapshot**, not an independently hermetic supply-chain audit. It is also not a claim that repeated installation yields identical bytes across runs.

## 3. Trusted bootstrap and frozen snapshot

Only after the bundled approval may the official installer execute, in its own disposable staging container with no YSM, credentials, home mounts, repository write access or host socket. Staging uses ordinary bridge egress for the trusted official installer; no independent domain allowlist or complete network-request audit is claimed. This network exposure must be disclosed in the bundled approval. Observed metadata hosts are maven.minecraftforge.net, libraries.minecraft.net, piston-meta.mojang.com, piston-data.mojang.com and files.minecraftforge.net; distinguish informational URLs from actual download entries. These hosts describe observed official metadata, not an enforced firewall. Permit the reviewed official bootstrap behavior; verify publisher-declared checksums and reject unexplained installed launch files or unknown launch inputs. Do not claim every transient installer request has been independently audited. YSM acquisition is outside installer staging, separately hash-verified, and is mounted only for the approved YSM test.

Verify all publisher-declared size/hash checks, including installer processor expected outputs. A mismatch, missing required declared value, unknown launch dependency or unexplained installed launch file is fatal. The reviewed harness policy classifies installer metadata/cache/log outputs separately from the actual launch closure. It does not individually re-audit every transitive library. The installer may perform its declared extraction/patching, but never start Minecraft or YSM during staging.

On completion, validate the expected production Forge entrypoint/arguments and every referenced file. Inventory/hash the complete installed launch tree; reject escaping symlinks and unknown referenced files. Make a frozen read-only snapshot, record its SHA-256 manifest, and use that exact snapshot for both runs. Truly generated outputs with no publisher expected hash receive recorded SHA-256 identities at this point; they are not silently substituted for outputs that do have expected hashes. Do not install again between control and YSM.

Before any Forge/YSM launch, inspect the approved container's Java version/release metadata: require major17, Microsoft vendor and nonempty exact build; record the tuple and assert it remains identical for staging/control/YSM. The immutable container digest pins the distribution; the human-readable build is an observed preflight fact.

## 4. Runtime isolation, evidence and stopping

Both target containers: network=none, no published ports, nonroot UID, read-only root/dependencies, dropped capabilities, no-new-privileges, default seccomp, private PID namespace, core dumps disabled, bounded4GiB/2CPUs/256PIDs. No credentials, home/repository/docker-socket mounts. Dedicated writable native extraction directory only where needed. Fresh fixed-seed world, loopback bind, RCON/query off, normal authentication settings. Set eula=true only after explicit linked EULA acceptance.

Production Forge control: ready<=180s, steady20s, normal console stop and exit<=30s. If control fails, stop. Repeat on a new writable game directory with exact YSM only. Job deadline25minutes. Unknown dependencies, failed isolation, checksum error, crash, unexplained network need, dirty snapshot or timeout stop the experiment; never retry on user PC or relax controls.

Capture raw target logs privately and emit only <=64KiB of escaped/sanitized allowlisted diagnostic/status text into normal Actions logs/summary. No asset bytes, worlds, binaries, screenshots, core dumps, arbitrary log uploads, caches, Packages or artifacts. Public repository means these sanitized logs are public. Report startup, native-load observation and shutdown separately. Server readiness cannot prove all RegisterNatives/worker drains or any client rendering. Signal9/137 is failure/inconclusive with OOM/timeout distinction, not clean shutdown.
