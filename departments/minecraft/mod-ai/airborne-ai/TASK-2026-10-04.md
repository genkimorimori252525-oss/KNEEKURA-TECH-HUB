# Task — Collect and organize airborne AI techniques

Date: 2026-10-04

## User goal

Collect the useful flying-creature AI techniques from the selected Minecraft MODs, keep provenance and failure history, and organize them so KNEEKURA can later build or evaluate airborne entities without rediscovering the same mechanisms.

This is a **research/design task**, not a request to modify a game MOD now.

## Definition of done

1. Reuse the existing Olympus flight research rather than duplicate it.
2. Pin usable upstream source entry points and license boundaries.
3. Extract flight, combat, landing, altitude, obstacle, group and ecology mechanisms.
4. Compare them with one common vocabulary.
5. Record known failure/repair lessons without inventing missing causes.
6. Produce a reusable Airborne AI Foundation architecture for Forge 1.20.1-oriented work.
7. Preserve runtime and source/binary uncertainty explicitly.

## Deliberately not claimed

- Full repository-wide analysis closure for each upstream MOD.
- Exhaustive Issues/PR history for every project.
- Decompiled distributed-JAR equality.
- Runtime GameTest/LAB pass.
- Performance benchmark.
- Permission to copy ARR assets or code.

## Next validation candidate

A future LAB experiment should compare three deliberately different profiles:

- **Tier A / Hero flyer**: route fallback + predictive combat + validated landing.
- **Tier B / Common hostile flyer**: direct steering + collision probe + cheap recovery.
- **Tier C / Ambient flock**: client-only Boids particles.

The first runtime acceptance should instrument state, intent, route mode, target, altitude band, landing candidate, stuck count and recovery reason. The experiment should fail closed on NaN, invalid touchdown support, stale route generation, self-target and unbounded landing retries.
