## What this slice implements

`asset_artifacts.py` rehydrates an existing M1 request through the existing Store:
request, captured profile, exact target version, spec, StyleProfile, references and
optional index must still agree. It accepts an inert, sealed blueprint for ONE
static Java item: 1..128 distinct axis-aligned cubes, explicit bounded UV rectangles,
a palette-index pixel grid, and explicit GUI/first-/third-person display transforms.
The limit is a resource ceiling, not a minimum-detail/quality score.

Export capture validates the actual Java JSON, editable native JSON, RGBA8 PNG and
all requested view PNGs before its first CAS write. It checks cube/face identities,
UV scaling, texture references and pixel equality between the standalone texture,
the native embedded texture and the sealed pixel grid. PNG framing, CRC, decompression
budget and row filters are checked. Unsupported formats/options fail closed.
The original accepted bytes, relative resource destinations and views are pinned.
`structural=PASS` never implies `visual=PASS`, live editor origin or Minecraft success.

`blockbench_guard.js` is the provider-side, single-use dispatcher. It accepts only
an authenticated status request or the sealed build request. Session/request/epoch/
operation IDs are checked. Runtime callers cannot submit a path, new blueprint,
script or raw upstream action. Concurrent/replayed mutations are rejected. A deadline,
changed project identity, unloaded texture or changed model fingerprint taints the
session; late async completion cannot start the next step. This is not cancellation
of arbitrary already-running JavaScript or protection from other same-user software.

`blockbench_host.js` adapts the reviewed command closure. The desktop must have no
project and only the guarded plugin. It records the actual newly created project
object, checks it around awaits, creates the sealed texture/cubes/display settings,
compiles the fixed native/Java codecs into memory, and captures bounded view PNGs.
It does not call upstream save/export/load-path commands. No user project is closed.

`asset_session.py` stages a new credential-bearing local bundle and performs one
explicit authenticated loopback attempt. It verifies the complete supplied upstream
Git blob before transformation. Exact patch anchors must occur once. The derivative
has a distinct plugin/global identity, fixed denied script/plugin/file operations,
a small incoming body limit and the upstream MIT notice. No download, installation,
editor/process launch or global setting change occurs. The M1 probe stays unchanged.

Local session files stay outside Git worktrees and the CAS. Writes are exclusive;
symlink paths and existing output/attempt markers are refused. An exclusive attempt
marker is fsynced BEFORE the mutable request. A connection loss, invalid result or
partial persistence is UNKNOWN, not a successful build or an automatic retry.
The public receipt binds request, blueprint, bundle hash, session, epoch and operation.
The token and generated bundle never enter CAS/Git/evidence uploads. Loaded code
attestation remains UNKNOWN: authentication is not proof of the editor's source bytes.
This is adapter-local single-operation accounting, not a second workflow/run manager.
