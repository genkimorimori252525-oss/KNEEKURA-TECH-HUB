# Scoped-control source interoperability gate

The paired gate uses the real TECH Python CLI and LAB Node entry point. It
prepares exact canonical TECH request/assertion bytes, retains their original
hashes in LAB's owner fixture, independently walks the actual Node import graph,
and checks that the resulting closure equals TECH's fixed 27-module registry.
All producer status and observations are explicitly source fixtures. It never
starts Minecraft, a JVM, an editor or a browser.

Run from TECH with an explicitly selected paired checkout:

```bash
KNEEKURA_LAB_SOURCE=/absolute/path/to/KNEEKURA-LAB \
  python -m pytest -q tests/test_minecraft_scoped_control_interop.py
```

Or run the LAB gate directly:

```bash
KNEEKURA_TECH_HUB_SOURCE=/absolute/path/to/KNEEKURA-TECH-HUB \
KNEEKURA_PYTHON=/absolute/path/to/python \
  node debug-workspace/bridge/tests/scoped-control-roundtrip.mjs
```

Without `KNEEKURA_LAB_SOURCE`, the pytest wrapper skips. An explicitly configured
missing checkout, absent test script, missing Node or failed subprocess fails the
gate; it never downloads or launches a replacement environment.

The check exercises owner inspection, selected action submission, action
inspection and a Cardinal-4 capture request through TECH's actual CLI and LAB's
real files. A stale owner status returns `OUTCOME_UNKNOWN`; initial action and
capture submissions return `REQUESTED`. Repeating the action from a fresh TECH
Store and repeating the capture return `ALREADY_RECORDED`, proving LAB retains
the replay fence independently of TECH receipt storage.

The same fixture opts in to `ARENA_EXIT` capture with one reserved slot and
calls the explicit finite `watch-triggers` command. A source producer row arrives
after the watcher is armed. The existing EvidenceRuntime consumes it, writes a
fixed capture marker with the sealed deadline, and retains a `PARTIAL` window
when no native image arrives. The watcher reports `WINDOWS_FINISHED` while the
requested capture remains uncertain. A second watch from a fresh TECH Store
returns `OUTCOME_UNKNOWN` without another marker or window. Inert TaskContext
offers only read-only owner reconciliation. The trigger row is selected for
private export and verified in the imported CAS.

The same fixture explicitly requests owner cleanup. Inspection before that
request reports `NEVER_SEEN`; inspection of the marker without a native cleanup
journal reports `OUTCOME_UNKNOWN`. Repeating cleanup from the fresh Store reports
`ALREADY_RECORDED`. An uncertain cleanup receipt gives only read-only
`experiment.inspect_cleanup` advice, and the finalizer preserves unknown shutdown
and cleanup instead of claiming an applied reset.

The fixture then writes a canonical structured observation through LAB's
EvidenceStore and finalizes the run through the existing evidence finalizer.
The real owner CLI exports private hash-named files outside that sealed run.
TECH's new `import-export`, `resume` and TaskContext commands consume those
generated bytes. The entire sealed run's filename/content-hash inventory must
stay unchanged across export and import.

Expected result: six retained evidence blobs, `UNKNOWN` execution and cleanup,
an `INCONCLUSIVE` assertion, `NOT_ESTABLISHED` runtime attestation, no replay and
only read-only reconciliation advice. Raw process logs and private paths are
not public output. The pending capture has no visual evidence or visual PASS.

The source fixture refreshes its simulated status heartbeat before each explicit
control command, retaining the production five-second freshness check and a
separate nonrenewable 120,000 ms fixture lease. This is transport interoperability
evidence, not a live owner or gameplay acceptance claim.

The hosted paired gate is configured verification, not completed evidence: its
current run stopped before source tests. Local paired results do not imply a
hosted pass or real runtime acceptance.
