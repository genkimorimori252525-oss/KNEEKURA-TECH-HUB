# Registered pre-experiment Tank rotation

`PRE_EXPERIMENT_TANK_ROTATION` is an optional, separate permission in the existing private scoped-owner registration. The source owner creates a new disjoint empty Tank region before an experiment. Existing Arena action permissions and bounds remain unchanged. The official world is identified in [world authority](../../DEBUG-WORLD-AUTHORITY-2026-10-04.md); native trials use preserved copies.

The private operator registration may include `tankRotation` with exactly eight fields: `schemaVersion: 1`, `scope: "PRE_EXPERIMENT_TANK_ROTATION"`, `rotationId`, `previousOwnerFileSha256`, `previousRecipeHash`, `previousTankEpoch`, `nextRecipeHash`, and `nextRecipe`. SHA-256 fields are lowercase64 hex characters; the predecessor file hash binds its complete raw bytes. `previousTankEpoch` identifies the saved Tank's `arenaEpoch`, distinct from the experiment Arena's epoch. The predecessor must report `GEOMETRY_VERIFIED` and its canonical recipe hash must match. `nextRecipe` uses the existing saved recipe shape: `v`, `kind`, `preset`, `dimensions`, `origin`, `dimension`, `shellBlock`, `environment`, `presentation`.

`prepareOwnerControl` binds the selection to the actual launch identity, request, grant, lease and experiment Arena epoch/revision. The selection cannot preselect runtime IDs, supply a command, change the lease or assert runtime acceptance. The final19-field plan is saved as `control/owner-tank-rotation.json`, its SHA-256 is sealed in `owner-envelope.json` as `tankRotationHash`, and the exact predecessor bytes are retained as `control/owner-tank-predecessor.json`. Reading these files verifies prepared intent only. It does not establish a native owner or attest current world state.

A maintenance request has empty `initial_state` and `actions`, `max_actions: 0`, `max_captures: 0`, visual mode `none`, no trigger configuration, and no allowed actions. The world registration requires both the existing `BOUNDED_DIAGNOSTIC_CONTROL` and the separate rotation permission in `minecraft:overworld`. The native owner never dispatches ordinary action, cleanup, trigger or capture requests during rotation. Its status is `TANK_ROTATION_IN_PROGRESS`; ordinary control readers reject that status. Registered Tank presentation remains disabled throughout maintenance.

Inner dimensions are integer1..64, inner volume at most65,536, allocated shell at most100,000 cells, and the next shell is disjoint from every preserved reserved region and the current Tank. At most16 predecessor regions participate. Shell cells become `minecraft:black_concrete`; interior cells remain air. The fixed environment values in the recipe are metadata: this operation does not apply time, weather, difficulty, gamerules, player placement or effects.

`PREFLIGHT → GENERATING → VERIFYING → VERIFIED` processes at most256 cells per server tick in each phase and yields between completed cells after25ms of elapsed tick work. A synchronous delegate or boundary save may exceed25ms; this is a scheduling budget, not preemption or a hard tick bound. All per-cell checks remain, and yielding does not renew the lease. The original owner lease remains finite and is checked before and after cell delegates. Source thread, run, server, Arena context, material/world identity, predecessor and installation receipt bytes are checked. Unloaded chunks, nonair cells or block entities are rejected without force-loading or clearing. Nonplayer entities in the old/current and new Tank regions and whole-level scheduled block/fluid ticks prevent generation; the latter is conservative because the pinned API lacks nondestructive regional enumeration. No entity removal or tick cancellation is used.

Before generation, `control/tank-rotation/native-reservation.json` is durably reserved and the saved world owner is marked `OUTCOME_UNKNOWN`. Every allocated cell is subsequently reread and the real world-save result is checked before atomic publication of a new `GEOMETRY_VERIFIED` owner. The saved Tank epoch advances by one; the old experimental Arena epoch is retained separately in evidence. `geometry-checkpoint.json` reports `GEOMETRY_READBACK_VERIFIED_NOT_TERMINAL`; only the controller's final authority check permits `receipt.json` with `VERIFIED`. Receipts bind owner-envelope, installation-receipt/file, material, world, request, lease, predecessor and next-recipe hashes. This proves geometry only, not reset fidelity or a dynamics baseline.

Interruption, expiry, drift, callback failure or incomplete publication produces `OUTCOME_UNKNOWN` and attempts durable `outcome-unknown.json` plus saved-owner invalidation. Cell counters count normally completed delegates and do not conceal potentially partial writes. Failed atomic temporary files, the reservation and predecessor remain available for inspection. There is no automatic retry, lease renewal, rollback or blind resume. A successful operation closes the old owner. Start a fresh experiment with the new saved epoch/recipe, freshly registered resource capsule and a bounded Arena; the old grant and display context cannot be reused.
