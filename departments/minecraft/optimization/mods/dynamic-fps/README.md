## DFPS-01 — state-aware graphics/render scheduling

[`WindowObserver`](https://github.com/juliand665/Dynamic-FPS/blob/499b5eed268ad0d55be7e3dc4e3384d53bacad7b/platforms/common/src/main/java/dynamic_fps/impl/feature/state/WindowObserver.java) chains GLFW callbacks and tracks `isFocused`, `isHovered`, and `isIconified`. [`DynamicFPSMod.checkForStateChanges0`](https://github.com/juliand665/Dynamic-FPS/blob/499b5eed268ad0d55be7e3dc4e3384d53bacad7b/platforms/common/src/main/java/dynamic_fps/impl/DynamicFPSMod.java) chooses states `FOCUSED / HOVERED / UNFOCUSED / INVISIBLE / UNPLUGGED / ABANDONED`. IdleHandler tracks cursor, player position/look direction and timeout; per-state config selects FPS/volume/graphics.

[`GameRendererMixin.render`](https://github.com/juliand665/Dynamic-FPS/blob/499b5eed268ad0d55be7e3dc4e3384d53bacad7b/platforms/common/src/main/java/dynamic_fps/impl/mixin/GameRendererMixin.java) conditionally modifies `Minecraft.noRender` expression to skip a frame unless `DynamicFPSMod.checkForRender()`. A second hook cancels `GameRenderer.renderLevel` when world is obscured by an appropriate screen/loading overlay.

**Target/guard**: when power state focused, normal render behavior retained; for unfocused/hidden/idle states selected configurable target limit applies. `checkForRender` computes wall-clock gap and allows one last transition frame (to update HUD); for target 0, skips all rendering, for positive low target, samples frames by elapsed milliseconds. [`WindowMixin.getFramerateLimit`](https://github.com/juliand665/Dynamic-FPS/blob/499b5eed268ad0d55be7e3dc4e3384d53bacad7b/platforms/common/src/main/java/dynamic_fps/impl/mixin/WindowMixin.java) reports at least **15 FPS** for inactive mode to keep client event/render loop responsive, **then** frame cancellation reduces actual submitted frames to target such as 1 FPS. This is a **client render skip**, not stopping server ticks or integrated-server logic.

**Correctness concerns**: hidden level effects and overlays, render callbacks from other mods, VSync behavior, scheduling callbacks, idle detection while camera/mouse/pad input changes, window focus regain. `MinecraftMixin.getFramerateLimit` also handles vanilla menu 60 FPS cap differently for selected cases, so compare menu and in-world separately.

## DFPS-02 — reversible low-graphics state and safe fallback

[`OptionHolder`](https://github.com/juliand665/Dynamic-FPS/blob/499b5eed268ad0d55be7e3dc4e3384d53bacad7b/platforms/common/src/main/java/dynamic_fps/impl/feature/state/OptionHolder.java) copies current vanilla graphics settings into static cached fields on DEFAULT→low state, then restores original values on return. It reduces clouds/particles/shadows/entity distance; MINIMAL further changes GraphicsStatus.FAST and ambient occlusion. Source does NOT promise every third-party graphics option is restored, only listed vanilla options. No claim of *permanently* better FPS while in foreground.

[`DynamicFPSMod.handleStateChange`](https://github.com/juliand665/Dynamic-FPS/blob/499b5eed268ad0d55be7e3dc4e3384d53bacad7b/platforms/common/src/main/java/dynamic_fps/impl/DynamicFPSMod.java) can call optional `System.gc()` based on config. **Forced GC makes benchmark results noisy** and is not itself a leak repair. It also hands state changes to `SmoothVolumeHandler`, can alter VSync and volume. `ModCompat` opt-out lets other mods request disabling loading overlay optimization, including RRLS guard. Source README warns battery monitoring may download an external native library at runtime but verifies predetermined hashes; device/browser/network permissions and native licensing outside this source slice.
