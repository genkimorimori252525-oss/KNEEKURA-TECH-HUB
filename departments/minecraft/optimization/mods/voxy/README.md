## Interpretation and correctness
A visual-only representation separate from vanilla simulation: sections at LOD n cover (32*2^n)^3 world-block extent; coarsening 8 samples to one does not imply exactly 8x RAM or FPS improvement because all levels, metadata, active cache, meshes, queues and native GPU buffers coexist. Baseline normal terrain render vs same visible range with LOD; DH matched visual quality comparison separately. CPU still performs ingest and meshing; GPU culling/indirect draws reduce per-frame CPU submission, not server ticks. Storage disk backend, compression, lighting fidelity, stale data and shader integration require further evidence. No claim of accelerated worldgen; upstream converts explored terrain and offers import; external worldgen add-ons are separate.
Risks: large resident cache/VRAM, ingestion backlog, GPU/driver incompatibility, thin transparent details lost by representative selection, source comment at VoxelIngestService line 168 notes potential concurrent mutation of chunk section during load ingest; not reproduced. GL4.6 author requirement. Pinned source has Iris version exclusion, history diff not yet reviewed. https://github.com/MCRcortex/voxy/issues/757 reports Intel iGPU hang (discovery only, no reproduced cause). Community reports mixed DH vs Voxy on different hardware: https://www.reddit.com/r/DistantHorizons/comments/1xfjbk3/why_do_you_use_dh/ and https://www.reddit.com/r/feedthebeast/comments/1tk7p1q/a_2612_greenfield_test_of_voxy_vs_distant_horizons/; not controlled evidence.
