## DH-LOD-01 — vertical full data → reduced columns → greedy meshed quads

**Source traversal:** [`LodDataBuilder`](https://github.com/EaseCation/distant-horizons-core/blob/a0d2dfe405a8cd8f3c50639378315484e5b56609/core/src/main/java/com/seibel/distanthorizons/core/dataObjects/transformers/LodDataBuilder.java) reads chunk columns, block states, biomes and lighting, writes `FullDataSourceV2` compact IDs/vertical span data. [`FullDataToRenderDataTransformer`](https://github.com/EaseCation/distant-horizons-core/blob/a0d2dfe405a8cd8f3c50639378315484e5b56609/core/src/main/java/com/seibel/distanthorizons/core/dataObjects/transformers/FullDataToRenderDataTransformer.java) reduces full data into `ColumnRenderSource` with detail-dependent maximum vertical slices, ignored blocks/cave rules, optional texture IDs, shade and light. [`LodQuadBuilder`](https://github.com/EaseCation/distant-horizons-core/blob/a0d2dfe405a8cd8f3c50639378315484e5b56609/core/src/main/java/com/seibel/distanthorizons/core/dataObjects/render/bufferBuilding/LodQuadBuilder.java) creates per-direction opaque vs transparent quads and **greedy merges adjacent compatible quads** (first premerge, then sort + merge in two axes). It packs **16 bytes per vertex / 64 bytes per raw quad** before merging in selected implementation.

- **Baseline:** rendering distant world as many full Minecraft voxel chunk meshes would create untenable geometry/draw work. The mod instead produces a **lossy summary of terrain** at selected LOD detail levels and compresses mesh representation.
- **Eligibility/guard:** detail scaling, min/max heights, transparent/ignored block policy, shader texture mode, cave rules; cave culling explicitly bypassed for dimensions with ceiling and when cave context unsuitable.
- **Thread/cache:** `LodQuadBuilder.THREAD_LOCAL` one per worker, bufferQuadCacheList and pooled byte buffers. Optimizes allocations but owner thread and lifecycle are distinct from renderer GL thread.
- **Semantics:** DH does **not** promise near field exact blocks or collision; terrain outline/color/light are approximate. Must test missing distant cliffs/water/glass, shade and translucent faces when lod detail changes.

## DH-LOD-02 — quadtree visibility, GL rendering and shader fallback

[`RenderBufferHandler`](https://github.com/EaseCation/distant-horizons-core/blob/a0d2dfe405a8cd8f3c50639378315484e5b56609/core/src/main/java/com/seibel/distanthorizons/core/render/RenderBufferHandler.java) selects active quadtree LOD sections/frustum and maintains GPU buffer references. [`LodRenderer`](https://github.com/EaseCation/distant-horizons-core/blob/a0d2dfe405a8cd8f3c50639378315484e5b56609/core/src/main/java/com/seibel/distanthorizons/core/render/renderer/LodRenderer.java) renders opaque/translucent passes, SSAO, fog and applies composed color/depth through renderer interfaces.

On **Minecraft 1.20.1 Forge**, [`MixinLevelRenderer`](https://github.com/DecoderCoder/Distant-Horizons/blob/eb6bf9ae7836bca986b429a28e2a9f94cb45ca77/forge/src/main/java/com/seibel/distanthorizons/forge/mixins/client/MixinLevelRenderer.java) inserts `renderLods` **before solid RenderType pass**, deferred LOD at translucent pass for shaders, fade at later passes. This is a **different stage than BFRC GPU occlusion** and Embeddium chunk mesh worker; shared framebuffers/shader depth mean strong compatibility risk.

[`GlDhMetaRenderer`](https://github.com/DecoderCoder/Distant-Horizons/blob/eb6bf9ae7836bca986b429a28e2a9f94cb45ca77/common/src/main/java/com/seibel/distanthorizons/common/render/openGl/GlDhMetaRenderer.java) owns FBO/color/depth textures, restores GL state, checks texture resize/recreate. OpenGL **3.3 minimum** stated by release notes. **Blaze3D** alternative module source includes `#if MC_VER <= MC_1_21_10` empty classes and is NOT the 1.20.1 rendering engine; don't port new 26.2 rendering claims to 1.20.1.

**LOD textures caveat:** [actual 3.2.0b code/commit `20f1cc...`](https://github.com/DecoderCoder/Distant-Horizons/commit/20f1cc438cbbb656342ea34720cdff5be170cc48) gates texture atlas upload/bind on `irisShadersInactive()`; Iris-compatible shader paths render **untextured** LODs rather than crash/incorrect texture. Author [release notes](https://www.curseforge.com/minecraft/mc-mods/distant-horizons/files/8389142) agree; do not promise textured LODs under Iris.

## DH-LOD-03 — bounded worldgen work and delayed persistence

[`RateLimitedThreadPoolExecutor`](https://github.com/EaseCation/distant-horizons-core/blob/a0d2dfe405a8cd8f3c50639378315484e5b56609/core/src/main/java/com/seibel/distanthorizons/core/util/threading/RateLimitedThreadPoolExecutor.java) records per-worker task runtime and, if `threadRunTimeRatio` less than 1.0, sleeps after task for approx `runTime / ratio - runTime`; this is **intentional throughput throttling** to prevent DH background work monopolizing CPU, not intrinsic algorithm acceleration. `purge()` is deprecated here because CompletableFuture wrappers may not be removed after cancellation.

[`DelayedDataSourceSaveCache`](https://github.com/EaseCation/distant-horizons-core/blob/a0d2dfe405a8cd8f3c50639378315484e5b56609/core/src/main/java/com/seibel/distanthorizons/core/util/delayedSaveCache/DelayedDataSourceSaveCache.java) coalesces updates by section position, triggers async save on expiration and closes the old `FullDataSourceV2` in completion handler. Inventory of `core/sqlScripts` shows SQLite schema/migrations and WAL journaling; database internals/full storage failure and crash atomicity **NOT fully audited**.

Correctness risk: partial LOD construction, data races during close, stale deferred LOD data after changing world/seed/dimension, storage bloat, chunk-unload races, propagation consistency and shader GPU lifetime.
